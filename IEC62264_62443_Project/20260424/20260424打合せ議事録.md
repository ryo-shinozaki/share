# 重点整理：他社事例紹介

## 1. K社（装置メーカー）事例  
### プロジェクト目的・狙いの設定

### 背景
- K社は、国内製造拠点中心の体制から、**真のグローバル企業への飛躍**を目指していた。
- そのために、**グループ共通の基幹システム再構築**を大きな目的として設定していた。
- その前段として、マクニカも参画し、プロジェクトの目的・狙いを経営・現場双方の視点で議論した。

### 当初の進め方
- プロジェクト目的を大きくA・B・Cのような単位で整理し、それを施策へ落としていく形で計画していた。
- ただし、プロジェクト進行中に事業環境が変化し、海外需要拡大を背景に**新棟建設**が前倒しで決定した。

### 途中で生じた変化
- 海外業績の向上により、もともと2年後を想定していた新工場計画が**2年前倒し**で始動。
- 新工場は**スマートファクトリー化**を前提とする方針となり、製造プロジェクトの中にデジタル化・IoT化の要素が一気に入ってきた。
- これにより、既存工場での改善中心から、**新棟をデジタル前提で立ち上げる構想**へと大きく舵を切った。

### 重要な考え方
- 一方で、環境変化があっても**ものづくりの本質は変えない**という考えを明確に維持した。
- 具体的には、以下のような製造のコアは不変とした。
  - リードタイム短縮
  - ジャストインタイム供給
  - 製造手順書（BOP）の整備
  - 標準作業の徹底
- つまり、**経営環境に応じて手段は変えても、ものづくりのコアコンピタンスは変えない**という方針で整合を取った。

### この事例からの示唆
- プロジェクトの目的は固定ではなく、経営環境・事業環境に応じて変化し得る。
- ただし、製造の中核となる考え方までぶらさないことが重要。
- そのため、**経営変革とものづくり変革を密に連携させながら、変える部分と変えない部分を明確にする**ことが重要との説明があった。

## 2. K社事例  
### 目標から施策・KPIへ落とし込む考え方

### OSTの考え方
マクニカでは、目標整理の考え方として以下の「OST」を用いているとの説明があった。

- O：Objective
  - 目指す姿
- S：Strategy
  - どのような方向性・切り口で改革するか
- T：Tactics
  - 実行に必要な具体施策

### この事例での整理
- Objective：
  - スマートファクトリーの実現
- Strategy：
  - 改革の切り口を3つの「I」で整理
    - IE：Industrial Engineering（ものづくり標準化）
    - IT：Information Technology（デジタル化）
    - IA：Industrial Automation（自動化）
- Tactics：
  - IE領域
    - ものづくり管理の徹底
    - 標準作業の進化
  - IT領域
    - 生産計画の高度化
    - 実績管理・PDCAの強化
  - IA領域
    - 主作業の自動化
    - 段取り・物流など付随作業の自動化

### KPI設定の考え方
- まず現状（As-Is）を把握し、To-Be施策を整理する。
- ただし、KPIは単純に現場施策の積み上げで決めるのではなく、**経営から見たあるべき姿からトップダウンで設定**する。
- 例としては、以下のような指標が挙げられた。
  - 可動率関連指標
  - 単位時間当たり生産数量
  - 人的生産性
- そのうえで、各施策がKPIにどの程度寄与するかを検証し、最終的に経営が求めるゴールに届くかを確認していく進め方であった。

### この事例のポイント
- KPIは「ISA-95で整理したから自然に出る」ものではない。
- 先に、
  - 何を目指すのか
  - どの切り口で改革するのか
  - その結果、何を改善したいのか
  を明確にする必要がある。
- そのうえで、KPIは**現場と経営をつなぐ指標体系**として設計することが重要である。

## 3. K社事例  
### MES切り出しと導入アプローチ

### MESの位置づけ
- MESは、データ集約の中心となる**「背骨」**として位置づけられた。
- 各種データは原則としてMESに集約する考え方で整理された。
- ISA-95は、主として**データモデルやアーキテクチャの整理軸**として活用された。

### 導入方針
- 実行段階では、MES領域は特に**現場起点のアプローチが効果的**と判断された。
- 導入対象は、以下のような観点から優先順位を付けて選定する考え方が示された。
  - ボトルネック工程
  - 成果が出やすい工程
  - 主力製品ライン
- まず1工場・1ライン等から始め、**順次展開**していく方式を採用した。

### PoCの重要性
- あるべき姿を描いた後、必ず**PoCを実施**して検証することが重要とされた。
- この点は、ユニオンツール側の「今年構想、来年PoC」という進め方とも整合するため、マクニカ側からも有効な進め方として言及があった。

### 注意点
- 現場起点に寄り過ぎると、個別最適に陥るリスクがある。
- 一方で、経営主導に寄り過ぎると、現場実態とずれて使いにくい仕組みになるリスクがある。
- そのため、
  - 全体計画
  - 現場実装
  - 経営判断
  を往復しながらつなぐ**ハブ機能**が重要、との説明であった。

## 4. R社（複合機メーカー）事例  
### ISA-95を使った生産システム整理

### 背景
- 赤木様より、マクニカ入社前に在籍していたR社での事例紹介があった。
- R社は複合機メーカーで、グローバル上位企業。
- 同社も生産系の基幹システムとして**AS400**を利用しており、センサー・周辺システムを含めた生産情報の管理が行われていた。

### 課題認識
- 2018年頃、グローバル製造企業にとって「本当にコアとなる生産システムは何か」を再検討した。
- IT部門、経営企画、SCM本部、グローバル工場のメンバーが参加し、ISA-95の機能階層をベースに議論した。

### 結論
- 最も差別化要素となるコアは、**レベル3（MES）**であると定義。
- 一方で、ERPや所要量計算、発注、在庫、原価管理などの上位機能は**ノンコア**と整理し、標準パッケージの活用を前提とした。

### アーキテクチャの考え方
- 3層構造で整理した。
  - レベル4：
    - SAPを導入
    - AS400も一部継続活用
  - レベル3：
    - ISA-95準拠のMESパッケージを導入
  - レベル0～2/3：
    - 各拠点の現場系システム群
- 現場系は拠点ごとの最適化を認めつつも、品質・納期・トレーサビリティなどの統制が必要な項目は、共通ルールでガバナンスを効かせる方針とした。

### 3層構造とした理由
- 固定部分と変動部分を分けるため
- モジュール化しやすくするため
- コア領域とノンコア領域を切り分け、柔軟性を持たせるため
- グローバルで品質・納期・トレーサビリティを管理しやすくするため

### グローバル共通MESの意義
- 各拠点はもともと個別最適化されたシステムを保有していた。
- それらがバラバラだと、品質問題やトレーサビリティ確認の際に横断的な追跡に時間がかかる。
- そのため、**グローバル共通MESにキー情報を集約し、必要に応じてドリルダウンできる構造**を採用した。
- これにより、全社共通管理と拠点個別最適の両立を図った。

### AS400の扱い
- AS400は依然として有効な基盤であり、とくに**データベースマシンとして有用**との評価が示された。
- したがって、全面廃止ではなく、役割を見極めたうえで継続活用する考え方が紹介された。

### この事例からの示唆
- 「何を共通化し、何を各拠点に残すか」を先に設計することが重要。
- MESを単なる収集システムではなく、**全体統制と現場活用をつなぐ中核**として位置づけるべきとの示唆があった。

# 主な質疑応答

## 1. KPI設定は現実的に可能か

### ユニオンツール側
- 現状、自社では生産現場を十分に把握し切れておらず、どのようなKPIを出せるのか見えにくい。
- 今後6か月の設計・計画段階の中で、AS400の整理や接続の検討を通じて、効果を示せるKPI設定が可能か不安がある。

### マクニカ側回答
- 品質など、既に重要指標として持っているものはベースラインになり得る。
- ただし、ISA-95で整理するだけではKPIは出てこない。
- まず、
  - 何を改革したいか
  - どの切り口で進めるか
  - 整理した先に何を得たいか
  を明確にする必要がある。
- その議論を行えば、KPIはかなり整理しやすくなるのではないか、との見解が示された。
- 赤木様からは、KPIは事業計画・経営指標と、生産として何を統制すべきかという**製造ガバナンスの視点**の両方から設計すべきとの補足があった。

## 2. 生産効率向上に向けた議論への支援可否

### ユニオンツール側
- 設備単体はすでに高効率であり、今後はそれらのつなぎ方や最適化によって全体生産性を上げることになるのではないか。
- どこをどう最適化すればよいかを一緒に議論できるか確認したい。

### マクニカ側回答
- ぜひ一緒に議論したい。
- こうした論点についても伴走しながら支援したいとの回答があった。

## 3. R社事例の図の見方について

### ユニオンツール側
- 生産形態別の欄が二段構造のように見えるが、どのように理解すればよいか。

### マクニカ側回答
- 各拠点はそれぞれ最適化された個別システムを持っている。
- その上で、下段に**グローバル共通MES**を置いて全社共通管理を行う構造。
- つまり、
  - 全社共通部分
  - 各拠点最適部分
  の二層が両立している、という見方になる。

## 4. スマートファクトリーではなくスマートカンパニーとしてどう考えるか

### マクニカ側
- ユニオンツールの構想は「スマートファクトリー」単独ではなく、より上位の「スマートカンパニー」の考え方に近いと認識している。
- 納期遵守、品質、コスト、リードタイムなどの観点も含め、製造だけに閉じない全体最適の視点が必要ではないかとのコメントがあった。

### ユニオンツール側
- 社長の考えはスマートカンパニーだが、現場として今まさに困っているのは**レベル2とレベル3の接続**である。
- その課題がスマートカンパニー実現とどうつながるかを説明できるようにしたい、との認識が示された。

### マクニカ側回答
- レベル2～3の取り組みがスマートカンパニー全体とどう結びつくかを図式化・整理できると良い。
- そのようなアウトプット作成も含め、共同で進めたいとの提案があった。

## 5. こうした議論を行うタイミング

### マクニカ側
- KPIや全体構想とのつながりを議論するのは、プロジェクト開始前がよいのか、進めながらかを確認。

### ユニオンツール側
- その種の議論は**プロジェクト開始後**に行う想定。
- コアメンバーは選出済みだが、具体的な活動はプロジェクト開始後に動き出す予定。
- 部門横断で進めるイメージである。
