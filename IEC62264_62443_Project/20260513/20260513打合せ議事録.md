# 工場標準化・セキュリティー強化プロジェクト マクニカ様打合せ議事録

## 会議概要

| 項目 | 内容 |
|---|---|
| 件名 | 工場標準化・セキュリティー強化プロジェクト マクニカ様打合せ |
| 日時 | 2026年5月13日 |
| 形式 | オンライン会議 |
| 出席者 | マクニカ：竹屋 親伸 様、丸山 千明 様、梅澤 晃幸 様、Akagi Nobuyuki 様 |
|  | ユニオンツール：篠崎 亮、吉原 一樹、若月 実、佐々木 幸次 |

## 議題

1. ユニオンツールの目指す姿に対するマクニカ様の理解共有
2. ユニオンツールの強みを踏まえた改革の切り口の確認
3. プロジェクト目標・施策ツリー案の確認
4. プロジェクト効果目標・KPIの考え方に関するディスカッション
5. プロジェクト体制、常駐対応、NDA手続きの確認

## 議事内容

### 1. マクニカ様からの説明趣旨

- 前回打合せで、プロジェクトの目的や効果について、一般的な内容でもよいので案を示してほしいとの要望があった。
- マクニカ様にて、ユニオンツールの公開情報、RFP、工場見学・ヒアリング内容を踏まえ、プロジェクト目標および効果目論見のたたき台を作成した。
- 6月に社長向けプレゼンテーションの機会があることを想定し、社長の考えやユニオンツール側の認識とずれがないかを確認しながら、提出版に向けて内容をブラッシュアップしたいとの説明があった。

### 2. ユニオンツールの目指す姿に対する理解

マクニカ様より、ユニオンツールの公開情報やIR資料を踏まえ、以下の理解が示された。

- 片山会長の「ものづくりに専念する」「世界最先端の技術を追求する」という考え、および渡辺社長の「スマートカンパニー」という方針を踏まえると、今回のRFPは、供給体制の強化を支える活動と位置付けられる。
- IR資料では、売上高・営業利益が過去最高を更新し、急増する需要に応えるため供給体制の強化を加速させる旨が示されている。
- その中でも、本プロジェクトは「スマートカンパニー」全体のうち、特にものづくり領域、すなわち「スマートファクトリー」領域を支える取り組みと考えられる。
- 営業戦略、技術戦略、ものづくり戦略全体がスマートカンパニーに含まれる可能性があり、そのうち工場システム標準化・セキュリティ強化が担う範囲を明確化する必要がある。

ユニオンツールからは、以下のコメントを行った。

- マクニカ様の理解は大きくは間違っていない。
- ただし、社長が「スマートカンパニー」という言葉で具体的に何を指しているかは、現時点では明確に把握できていない。
- これまで提示しているスマートカンパニー像は、篠崎からの提案・仮説であり、今後社長の考えを確認する必要がある。

### 3. ユニオンツールの強みに関する整理

マクニカ様より、ユニオンツールの強みとして公開情報に記載されている「技術力」「生産設備」「財務体質」をもとに、以下の本質的な切り口が示された。

#### 技術力・製造ノウハウ

- PCBドリルの設計・性能そのものに加え、培ってきた製造ノウハウを生かして、製品の付加価値を高めることが強みである。
- 単なる増産ではなく、技術に技術を上乗せし、他社と差別化することが重要である。

#### 生産設備

- 生産設備をほぼ100%自社開発している点が特徴である。
- 設備開発技術者と製造現場が密に意見交換し、製造効率を高めていることが本質的な強みである。
- 自社設備を持つことにより、需給変動にスピーディに対応できる。

#### 経営体質

- 財務体質が堅実であり、創業以来の黒字経営、借入金なし、高い自己資本比率が強みである。
- その本質は、従業員が本業に専念できるリスクの少ない経営環境を会社が用意している点にある。

ユニオンツールからは、マクニカ様の整理について、方向性として問題ない旨を回答した。

### 4. プロジェクト目標・施策ツリー案

マクニカ様より、ユニオンツールの強みを生かして供給体制を強化するためのプロジェクト目標・施策ツリー案が示された。

#### 技術力・製造ノウハウの強化

- 100%自社開発の強みを維持しつつ、工程単位の自動化からライン全体での工場自動化へ進化させる。
- これにより供給力を拡充する。

#### 生産フローの進化

- 単体設備の強みを、設備間・工程間をつなぐフロー全体の強みへ発展させる。
- 需給変動へのスピーディな対応、設備開発者と製造現場のさらなる連携強化を図る。
- そのための手段として、ISA-95を含むIEC等の国際標準への準拠が重要となる。

#### 経営体質・情報基盤の強化

- 素材、技術、製造ノウハウをリスクから守り、さらに発展させる情報基盤を整備する。
- セキュリティ強化、情報基盤整備、見える化により、経営・業務判断に必要な情報を扱える状態を目指す。

### 5. 現状課題に関する整理

マクニカ様より、RFP記載事項および工場見学・ヒアリングから見えた課題として、以下が示された。

#### RFPに記載されている課題

- AS/400上にERP機能とMES機能が一体化しており、将来の機能差し替えに懸念がある。
- IoT機器導入の都度、接続方法や連携方法について個別相談・個別対応が必要となっている。
- 実験環境と本番環境の分離が不十分で、技術情報の漏洩リスクがある。
- セキュリティポリシーが不十分で、社外説明および社内説明において全体像を示しづらい。

#### マクニカ様が追加で認識した課題

- 工程単位の自動化は進んでいるが、ライン全体での工場自動化に進化させる余地がある。
- 積み替え、搬送など、製品価値に直接寄与しない作業の改善余地がある。
- 工場エリアによって自動化レベルにばらつきがある。
- ERP層にIoT接続プログラムが直接つながっており、システムとデータの結合が曖昧になっている。
- 設備のスループットが工場全体のアウトプットに直結しており、ボトルネック設備の見極めが必要である。
- 公開財務情報から算出した在庫日数が高い可能性がある。ただし、全社ベースの数値であり、PCBドリル単独の数値ではない。
- 原材料を中心に、帳簿・現物不一致が見られる可能性がある。
- 現場レベルのデータ活用は進んでいる一方、経営レベルでのデータ活用には改善余地がある。
- 物理セキュリティの観点でも、ブラックボックス化された技術・ノウハウの持ち出しリスクを考慮すべきである。

ユニオンツールからは、RFP範囲を超える黄色領域として示された課題についても、認識としてはその通りであり、それを解消するための活動でもある旨を回答した。

### 6. 効果目標・KPIに関する議論

マクニカ様より、プロジェクト効果の考え方として、PL観点とBS・キャッシュフロー観点の2つが提示された。

#### PL観点

- PCBドリル、特にULFコートドリルの需要増に対して、市場が求める水準まで供給能力を引き上げることを効果目標にできないか、という案が示された。
- IR資料には販売数量推移のグラフがあるが、数値軸がないため、具体的な目標値設定には追加情報が必要である。
- NDAの範囲も踏まえ、可能であれば市場要求水準や生産能力に関する数値情報を共有し、目標値を検討したいとの提案があった。

#### BS・キャッシュフロー観点

- 在庫削減を効果目標にできないか、という案が示された。
- 公開財務情報から、平均棚卸資産約124億円、年間売上原価約245億円をもとに算出すると、在庫日数は188.6日となる。
- ただし、この数値は全社ベースであり、PCBドリル、エンドミル、その他製品が混在している。
- 在庫の持ち方には各社の方針があり、目標設定には製品別・事業別の切り分けが必要である。

#### ユニオンツールからのコメント

- 在庫数値はPCBドリル単独ではなく、全体数値であるため、PCBドリルだけで見る必要がある。
- 生産能力に関するデータが十分に取れていないため、どこがボトルネックで、どこに手を打つべきかの分析が難しい。
- 生産本数を上げる取り組みは既に別活動として進めており、本プロジェクトの直接成果として数量増をゴールに置くことには距離がある。
- 一方で、必要なデータを取れるようにし、分析可能な状態にすることは、本プロジェクトの範疇に入る。
- ISO 22400シリーズに従ってKPIを計算できる状態になっておらず、全社統一した分析ができないことが課題である。
- 今回のプロジェクトとしては、最終的な生産数量や在庫削減そのものではなく、その前提となるデータ取得、情報基盤、標準化、見える化を中間指標・成果として置くほうが分かりやすい。

### 7. 製品別・業務別の論点

マクニカ様より、多品種製品における中間品・SKU・品番設計の考え方について質問があった。

- 市場・顧客の動き、営業情報、業界データ、フォーキャストを製造計画へ一気通貫で流すことが重要である。
- 品種が多い場合、中間品をどのように持ち、受注後にどこから加工するかが、生産性や在庫の持ち方に影響する。
- ISA-95のレベルごとに役割分担を明確化し、レベル5からレベル0まで一体的に動かすことが重要である。
- PLM領域でSKUや品種をどのようにブロック化するかも論点になり得る。

ユニオンツールからは、以下のコメントがあった。

- エンドミルでは一部、中間品的な考え方を実施している。
- ドリルでは、先端部分とシャンク部分を接合する前までは共通的に扱えるが、接合後は品番が決まる。
- 以前は中間在庫を持つやり方もしていたが、試行錯誤の結果、現在は途中で止めずに一気に生産する方がよいという考えに変わっている。
- エンドミルについては、在庫が多いにもかかわらず欠品するという問題がある。
- PCBドリルについては、設備台数の増加に比例して生産数が上がっていない可能性があり、設備のフルアウトプットを出せるようにすることがポイントである。

### 8. AS/400整理とIT部門連携

マクニカ様より、AS/400の現状整理について以下の提案があった。

- AS/400内のライブラリ、プログラム、データベース、業務別のデータ構造をまず整理する必要がある。
- どのデータが、どのタイミングで、どのように生成・利用されているかを把握することが最初に実施すべきことである。
- IBM i関連ではAI活用ツール等も出てきており、現状整理に活用できる可能性がある。
- AS/400のデータとプロセスをISA-95等の考え方に沿って整理し、役割分担を明確にしたうえで、何が見えるのか、何が見えないのかを整理することが重要である。
- ユニオンツールのIT部門との連携が必要である。

ユニオンツールからは、以下のコメントを行った。

- AS/400の整理には現時点で着手していない。
- AS/400、業務、データ、プロセスの整理が重要であることは認識している。
- 自社だけで進めるのが難しいため、今回コンサルティングを依頼している。
- その領域についてマクニカ様に支援していただきたい。

マクニカ様からは、AS/400、IBM i、ISA-95に基づく整理、ERP・MES導入、プロセス分析の経験を踏まえ、支援可能であり期待してよいとの回答があった。

### 9. プロジェクトの位置付けとゴール設定

議論の結果、以下の方向性が確認された。

- 「スマートカンパニー」「スマートファクトリー」全体を最上位に置くと、生産数量増、在庫削減、供給力拡大などがゴール候補になる。
- 一方、今回のRFPに基づく「工場システム標準化・セキュリティ強化プロジェクト」は、その全体構想のサブプロジェクトとして位置付けたほうが整理しやすい。
- 本プロジェクトの直接的なゴールは、生産数量増や在庫削減そのものではなく、それらを支える情報基盤、標準化、セキュリティ、見える化の整備とするのが妥当である。
- 経営視点・業務視点で必要な情報を整備し、供給力拡大に向けた現場活動を下支えする位置付けとする。
- ISA-95、IEC 62443、ISO 22400等への準拠・活用を、ゴールやKPIの中間指標として検討する。
- マクニカ様にて、今回の議論を踏まえ、RFP範囲にフォーカスしたゴール・KPI案を再検討する。

### 10. プロジェクト体制・常駐対応

マクニカ様より、前回提案の体制図に対する追加提案があった。

- プロジェクトマネージャーおよびプロジェクトリーダーが、ユニオンツール側のプロジェクトメンバーの一員として入り、オンサイトで支援する体制を提案する。
- ワーキング定例会は、オンサイトとオンラインを組み合わせて実施する。
- 見積額自体は変更しない方針である。
- ただし、訪問頻度が増えるため、旅費等の扱いは別途試算・調整が必要となる可能性がある。

ユニオンツールからは、常駐対応は評価ポイントになり得るが、詳細については丸山様と別途直接相談したい旨を伝えた。

また、篠崎より、社長からの指示もあるため、体制・常駐に関する論点は別途相談したい旨を伝えた。

### 11. NDA手続き

- NDAについては、書面で進めることを確認した。
- ユニオンツール雛形を用い、ユニオンツール発信で進める。
- ユニオンツール社内で最終決裁を通した後、3部印刷してマクニカ丸山様宛に送付する。
- マクニカ様から提示される資料にも機密情報が含まれるため、双方でコンフィデンシャル情報の扱いに留意する。

## 決定・確認事項

- マクニカ様のユニオンツール理解、強みの整理、供給体制強化という方向性は大きく相違ない。
- 社長が考える「スマートカンパニー」の具体的範囲は未確認であり、今後確認が必要である。
- 本プロジェクトは、スマートカンパニー／スマートファクトリー全体の中の、工場システム標準化・セキュリティ強化を担うサブプロジェクトとして整理する方向。
- 本プロジェクトのゴールは、生産数量増や在庫削減そのものではなく、それらを支えるデータ取得、情報基盤、標準化、セキュリティ、見える化を中心に再整理する。
- AS/400の現状整理、データ・プロセス整理、ISA-95に基づく役割分担整理は重要な初期論点である。
- NDAはユニオンツール雛形で書面締結を進める。
