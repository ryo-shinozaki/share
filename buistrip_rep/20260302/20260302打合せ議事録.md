## 3. 共有事項（2025年活動の要点：資料ベース）
### 3.1 2025年の実施事項（概要）
- 量産シミュレーションの実施  
  - 対象：HSLB、CSELB、HWLB、CWLB
- ロジック式の改善（係数・因数見直し）
  - 分布タイプ変更：正規分布 → **γ（ガンマ）分布**
  - リードタイム見直し
  - 変動型アラーム設定の見直し（ポアソン分布等の扱い含む趣旨）
- 需要予測を加味したロジック式の検討・試用（対象：HWLB、CWLB）
  - 出荷実績をもとに増産係数を算出（Excelレベルの簡易推計）

### 3.2 量産テスト結果の結論（資料）
- **既存在庫の適正化（HSLB、CSELB）には有効**
  - 見附工場の在庫減（調整）への寄与：寄与度▲1.8%、寄与率88%
- **新製品／切替後継型番（HWLB、CWLB）には、このままでは有効でない**
  - 生産能力制約、海外子会社需要、切替需要の読み違い等により欠品が発生

### 3.3 補足（滞留在庫：Pランク）に対する効果感
- 動きの悪い（スロームーバー）領域は「作らない制御」を入れても**減りにくい**一方、**増えにくくする効果**はある
- 見附工場全体の滞留在庫減▲8.9%に対するHSLB・CSELB寄与：寄与度▲2.9%、寄与率33%  
  - 構造的に滞留在庫が大きく、売れ筋の制御に比べ全体寄与が相対的に小さい、という認識を共有

## 4. 議論まとめ（論点・合意形成のポイント）

## 4.1 プロジェクト名称変更（方針の再定義）
- 旧：滞留在庫削減プロジェクト  
- 新：**適正在庫実現プロジェクト**（アンケートで名称決定）
- 新名称の意図（資料・発言の趣旨統合）：
  - 売れる製品が常時ラインナップされている状態を作る
  - 必要にして十分な在庫量を維持する（欠品抑制も重視）

## 4.2 「後継型番の初期在庫見積（需要予測）」が重要課題
- 課題認識：
  - 切替局面では、単純な過去トレンド延長（簡易な増産係数）では不足
  - 欠品・過剰の両方が起こりうる（初期見積が粗いことが在庫増の一因）
- 欠品／失敗要因として言及されたもの（要旨）：
  - 生産能力（例：コーティング能力が旧系列より低い等）
  - 不良・工程負荷の影響
  - 営業側の依頼／実注入力の遅れ・失念
  - 海外側の切替需要の取り込み不足
  - 需要構造の変化（用途が変わり発注が想定以上になる 等）
- 方向性：
  - まずは「新製品の完全予測」ではなく、**型番切替時の需要予測シミュレーション**としてスコープを絞る
  - AS（図面・基幹）情報だけでは足りない可能性があり、用途・市場情報など追加因子の検討が必要

## 4.3 スマート生産システム（Excelからの置換）方針
- 現状課題（要旨）：
  - Excelが重い／情報過多／運用が属人化しやすい
  - 現在は「判断材料提示」に留まり、最終判断が人（生産管理の勘・経験）に偏る
- 目指す姿（要旨）：
  - 基本はシステムが生産指示を出す
  - 変更時は、変更プロセス（承認・上長確認等）を設けて統制する
- 適用範囲の考え方（会話の結論に近い整理）：
  - **売上に効くところへ集中**
  - 「売上本数上位80%」≒「型番全体の上位20%未満」に重点適用
  - トラブルが多いカテゴリ（DLC/CBN/UDC等の言及あり）は一旦対象外とし、比較的安定している領域（UTコート、ハードマックス、HWコート等）から適用を検討

## 4.4 リードタイムの扱い（初期方針）
- 議論の方向：
  - リードタイムをモデルに組み込むのは難易度が高く、現状のカオス状態ではリスクが高い
  - 当面は**リードタイム固定**（妥当値を置く）で進め、安定化に合わせて見直す、という整理が有力

## 4.5 スケジュール感（現時点の希望）
- 希望：
  - 2026年度上期でプロトタイプ含め「操作性のある状態」へ
  - 2026年度下期に、売上上位80%型番群へ導入・適用を進めたい
- ただし：
  - 体制（担当者アサイン）と、データ準備・仕様固めが前提条件
  - まず「大枠のタイムスケジュール」を作る必要がある、という認識を共有

## 5. KGI確認（資料の数値を採用）
- 対象範囲：見附工場EM製品在庫ならびに中間在庫
- 期限：**2026年12月末まで**
- KGI①：売上本数上位80%型番における欠品率 **1.0%以下**
- KGI②：売上本数上位80%型番において「欠品が発生した型番」の割合 **20%以下**  
  - 2025年度実績「欠品発生型番割合40%」の半減を目標

## 7. Claude Code Team / Agent Teams 紹介（後半セッション要旨：新保・林）
### 7.1 紹介内容（ポイント）
- Claude（他AI含む）で「複数エージェントに役割を持たせて協働させる」機能（Agent Teams）の活用例を紹介
- 1対1のチャットではなく、以下のように役割分担させて成果物の品質を上げるイメージ
  - リーダー（取りまとめ）
  - エンジニア（実装）
  - デザイナー（UI）
  - テスター（検証） など

### 7.2 デモ・事例（会議内での紹介）
- 事例1：ボードゲーム用アプリ（オセロ、将棋）
  - チームで議論しながら生成するため時間はややかかる（目安10分程度）が、完成物の品質が高い、という所感
- 事例2：陸上養殖（例：ヒラメ）の事業計画書
  - Markdownで計画書を生成 → 資料化（PowerPoint化）まで短時間で作成可能、という流れを紹介
  - 補助金リストや調査観点など、人手だと時間がかかる要素のたたき台を素早く作れる点を評価
- 事例3：採用ページ改善レポート
  - SEO、デザイン、セキュリティ等を並列エージェントで検討させ、示唆をまとめる使い方を紹介

### 7.3 会議内で出た位置づけ（要旨）
- AIに「仕事をさせる」だけでなく、複数案を作らせて「人が選ぶ・検証する」スキルが重要
- 社内で使いこなす人材育成（短時間の研修）を検討したい、という方向感
