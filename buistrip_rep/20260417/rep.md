## リザバーコンピューティング

リザバーコンピューティングは，入力層・リザバー層・出力層からなる時系列データ向けの計算方式であり，内部のリザバーを固定したまま，主に出力層のみを学習する点に特徴がある。これにより，通常の再帰型ニューラルネットワークと比べて学習計算量を抑えやすく，少ないデータや短い学習時間でも扱いやすい。  
また，入力の履歴を内部状態として保持できるため，波形予測，異常検知，音声認識などの時系列信号処理と相性がよい。さらに，リザバー部は電子回路，光回路，材料デバイスなど多様な物理系で実装できるため，高速・低消費電力なエッジAIへの展開が期待されている。

### 日立製作所

日立製作所の展示では，リザバーコンピューティングを用いた時系列信号処理と異常検知の活用例が紹介されていた。入力信号の特性を短時間で学習し，次に到来する信号を予測することで，予測値と実測値のずれから異常を検知する考え方である。  
設備やプラントの状態監視への応用が想定されており，連続的に流れるセンサデータを扱う用途と親和性が高い。リザバーをFPGA上に構成することで，シリアル信号処理に強く，低消費電力かつ高速に動作する点が強調されていた。

### 九州工業大学

オンライン学習機能付リング型リザバー計算FPGAシステムを題材に，IoT機器をクラウドへ常時接続した場合の通信量増大に対して，エッジ側で時系列データを学習・処理する構成を提案するものであった。狙いは，センサ近傍で予測や異常検知を実行し，通信負荷と遅延を抑えながら，現場で継続的に適応できる計算基盤を実現することにある。  
適用例としては，振動データを用いたポンプ異常検知と，長期モニタリングデータに対する異常検知が挙げられていた。前者では正常時と異常時の波形差を用いて異常を検出し，後者では長期観測データから出力誤差の増大箇所を抽出していた。

## 講演“「Claude」が追求する安全性と最新活用事例”

登壇者：Anthropic Japan社 岡田大志氏  

### 1. 講演概要
本講演では、Anthropicがなぜ企業向けAIとして評価されているのかを、「安全性」と「実務活用」の両面から説明していた。主張の中心は、Anthropicは単に高性能な生成AIを提供する会社ではなく、**信頼でき、解釈可能で、制御可能なAIをつくることを使命とする企業**であるという点である。  
そのため、モデル性能の向上だけでなく、企業が本番業務で安心して使えるよう、法的な統治、学習方法、監査、権限制御、データ保護まで含めて一体で設計していることが強調された。

### 2. 安全性に関する主な説明
Anthropicは、AIの恩恵と同時にリスクも正面から扱う姿勢を重視している。講演では、安全性を単なる理念ではなく、会社の仕組みに組み込んでいる点が特徴として紹介された。  
また、Claudeは**Constitutional AI（憲法AI）** という考え方で訓練されており、AIが従うべき原則を明文化し、その原則に沿って応答するよう設計されている。これにより、単に危険な出力を後から止めるのではなく、最初から「役に立ちつつ危険を抑える」方向でモデルを育てているという説明であった。  
加えて、レッドチーミング、脱獄攻撃対策、外部研究者による検証、第三者認証、監査ログ、アクセス統制、人間による最終確認など、多層的な安全策が製品全体に実装されていることが示された。

### 3. 製品・用語の要点
- Claude Code  
  開発者向けのAI支援基盤。コードベース全体を理解し、調査、設計、実装、テスト、改修まで一連の開発作業を支援する。単なるコード補完ではなく、**AIの開発パートナー**として位置付けられていた。

- MCP  
  AIと社内システム、外部ツール、データをつなぐ共通規格。個別連携を都度作るのではなく、標準的な方法で接続できるため、AI活用の拡張性を高める。

- Claude Agent SDK  
  Claude Codeで使われているエージェントの仕組みを、自社製品や社内システムへ組み込むための開発キット。自社専用のAIエージェントを作るための土台といえる。

- Managed Agents  
  AIエージェントを本番運用するための実行環境を、Anthropic側で用意・管理する仕組み。企業はインフラ構築の負担を減らしつつ、安全に運用しやすくなる。

- Claude Cowork  
  非エンジニア向けの業務支援アプリ。ファイル操作、ブラウザ操作、各種ツール連携を通じて、調査、資料作成、申請書作成などをまとめて進められる。**相談相手ではなく、仕事を完了させるAI**として紹介されていた。

### 4. 講演で紹介された事例
#### 4-1. マネーフォワード社
マネーフォワード社では、最初から全社導入するのではなく、少人数で複数のAI開発支援ツールを比較し、最も手応えのあったClaudeを採用したという。特に重要なのは、その後の展開がトップダウンではなく、**現場のエンジニアが自発的に導入を希望して広がった**点である。  
講演では、200人以上のエンジニアが導入を希望し、API実装が従来の2日から約5時間に短縮、新人の立ち上がりも1週間から1日に短縮されたと説明された。さらに、多くの利用者が日常的に使っており、**1人あたり週7時間程度の業務最適化**につながっているとのことであった。  
この事例は、Claude Codeが単なる新技術ではなく、現場が「実際に使いたい」と感じる実務ツールとして定着していることを示している。

#### 4-2. 楽天社
楽天の事例では、Claude Codeが**“もう一人のエンジニア”として機能した**ことが紹介された。対象は、複数言語が混在する大規模な既存システムの改修であり、約250万行のコードを理解させ、約7時間連続で作業を継続させたという。  
従来は熟練エンジニアが長時間張り付く必要があった作業だったが、Claude Codeの活用により、24日かかっていた業務が5日に短縮され、**タイム・トゥ・マーケットは約80％削減**されたと説明された。  
この事例は、AIが局所的な補助ではなく、プロジェクト全体を踏まえて長時間・高難度の開発作業を担える段階に近づいていることを示すものである。

#### 4-3. 非エンジニア向け活用例
講演では、Claude Coworkの例として、「新会計システム導入の稟議書を500万円予算で作成する」という業務も紹介された。通常のチャット型AIでは、本文作成、修正、承認ルート確認、Word整形などを人が何度も往復して行う必要がある。  
一方、Coworkでは、過去の稟議書参照、社内規程確認、指定フォーマットでの文書生成、上長への送付準備までをまとめて実行できるイメージが示され、**7往復・約25分の作業が、2往復・約3分に短縮される**という説明であった。  
これは、AI活用が開発部門だけでなく、管理部門や企画部門にも広がる可能性を示す例といえる。

## 5. まとめ
本講演の要点は、Claudeの価値が「高性能な生成AI」であること以上に、**企業が安心して本番業務に組み込める安全性と統制を備えたAI基盤**である点にある。  
特に、エンジニア向けにはClaude Code、非エンジニア向けにはClaude Cowork、自社組み込み向けにはAgent SDKやManaged Agentsを展開することで、個人利用ではなく組織利用を前提とした設計が徹底されていた。  
事例から見ても、Claudeは単なる文章生成や補助的な自動化にとどまらず、**開発・事務の両面で業務全体の時間短縮、品質向上、再現性向上を実現する実務基盤**として活用が進んでいると理解できる。
