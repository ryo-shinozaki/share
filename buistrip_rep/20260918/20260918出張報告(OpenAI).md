### 1.2 OpenAI Daybreakによるセキュリティ対策

サイバー攻撃の加速を背景に、防御側もAIを活用して脆弱性を早期に発見し、攻撃を受ける前に対策することが重要との説明があった。脆弱性の発見から攻撃までの時間について「10時間」との紹介があった。

Daybreakについては、審査・承認を受けた企業に対し、セキュリティ検証を目的とする質問への制限を調整したモデルをAPI等で提供するとの説明があった。自社コードに対して「侵入経路を見つけて」と依頼するような、許可された対象の防御力を高める用途が想定されている。

公式資料では、Daybreak Blueは正当な防御目的の作業に対する応答拒否を減らしたモデルへのアクセス、Daybreak Redはより高度なセキュリティ研究向けの専門モデルへの別途承認されたアクセスとして整理されている。単に制限を解除するものではなく、承認された利用者・組織・利用環境と、評価を許可された対象の範囲で利用する仕組みである。[Models and Trusted Access](https://learn.chatgpt.com/docs/cyber-safety)

### 1.3 Codex Security

Codex Securityプラグインは、セキュリティ関連のチェック項目や実施手順をまとめたものであり、専門知識が十分でない開発者でも、コードのセキュリティリスクの調査を進めやすくするとの説明があった。当日は「13件のスキルをまとめたもの」と紹介されたが、今回参照した公開資料では件数の裏付けは確認できていない。

公式資料では、コードをスキャンして脆弱性の候補を検証し、検出根拠と修正方針を示す機能が説明されている。ローカルのプラグインは、ChatGPTデスクトップアプリ内のCodexまたはCodex CLIで利用する。当日はGitHub Copilotでは動作しないとの説明があり、今回確認した公式の導入手順もCodex向けである。[Codex Security plugin quickstart](https://learn.chatgpt.com/docs/security/plugin)

検出した問題へのパッチ作成・適用も可能との説明があった。公開資料でも、検出結果の確認、修正案のレビュー、修正後の検証までを一連の作業として扱っている。また、CLIとTypeScript SDKにより、既存の開発ツールや継続的インテグレーション（CI）への組み込みが可能である。Codex Security APIの具体的な提供形態については、利用を希望する環境に合わせて確認する必要がある。[Scaling cyber defenders with Daybreak](https://developers.openai.com/blog/scaling-cyber-defenders-with-daybreak)

### 1.4 Astraによる開発支援

Astraにより、セキュリティ分野や未知の課題への対応能力が向上しているとの説明があった。

公開資料では、GPT-6 Astraは複雑な推論、コーディング、コンピューター操作、調査、文書作成に対応するモデルとして紹介されている。コードの作成だけでなく、調査や操作を含む業務への適用も検討対象となる。一方、今回確認したモデル概要だけでは、当日の説明にあったセキュリティ能力の向上を定量的に評価することはできない。[GPT-6 Astra Model](https://developers.openai.com/api/docs/models/gpt-6-astra)

2026年9月25日（金）14:00～15:00に、Astraによってコード開発がどのように変わるかを説明するイベント[「GPT-6 Astra で変わるソフトウェア開発」](https://webinar.openai.com/gpt-6-astra-jp/)の案内があった。

### 1.5 PC操作による業務自動化

AIがパソコンを操作し、RPAのように業務を自動化する機能Computer useについて説明があった。

Computer useは、画面の情報をもとに、クリック、文字入力、スクロールなどの操作を行い、ブラウザやデスクトップアプリの処理を進める機能である。公式API資料では、フォーム入力やユーザー操作のテストなどが用途として挙げられている。APIで利用する場合は、操作環境の用意と、モデルが要求した操作を実行する仕組みを開発者側で用意する必要がある。[Computer use](https://developers.openai.com/api/docs/guides/tools-computer-use)

当社では、画面への転記や定型的な入力作業などが適用候補と考えられる。今後、具体的な対象業務を選び、処理精度、例外時の動作、作業時間の削減効果を評価する機会を設けたい。

### 1.6 操作・利用記録の取得

ChatGPT EnterpriseではCompliance APIを通じてログを取得でき、API PlatformにもAudit Logs APIがあるとの説明があった。公開情報では、両者の対象は次のように整理される。

| 機能 | 主な対象・用途 |
| --- | --- |
| Compliance API | ChatGPTワークスペース等の対応する記録を取得し、監査・調査システムへの連携に利用する。対象イベント、権限、保持期間はAPI仕様の確認が必要。 |
| API Platform Audit Logs API | API Platformの組織内で発生したユーザー操作や設定変更の監査記録を取得する。 |

出典：[Compliance API and audit events](https://learn.chatgpt.com/docs/enterprise/compliance-api)、[Audit Logs API Reference](https://developers.openai.com/api/reference/typescript/resources/admin/subresources/organization/subresources/audit_logs)

なお、これらのAPIでPC上のすべての操作を記録できるとは限らない。公式資料も、ローカルファイル操作、スクリーンショット、ブラウザ操作などがすべてCompliance APIに記録されるとは想定しないよう説明している。導入時には、必要な監査項目を定め、取得可能な記録と照合する必要がある。[ChatGPT Work local security](https://learn.chatgpt.com/docs/enterprise/chatgpt-work-local-security)

## 2. 所感と今後の対応

請求書払いとすることで、OpenAIに当社に営業担当がつくことになる。情報入手とサポートには有効であり、OpenAI Daybreakについても営業担当がいなければ承認を得るのは難しい。

今回の打ち合わせでは、AIの活用範囲が、コードや文書の生成から、脆弱性の調査・修正支援、PC操作を伴う業務の実行へ広がっていることを確認した。当社においても、開発品質の向上と定型業務の効率化の両面で活用の余地があると考える。

セキュリティ分野では、OpenAI DaybreakとCodex Securityは非常に有効である。専門知識を補う支援機能として活用し、修正の採否は担当者が確認する運用を検討したい。

今後は、以下の事項を確認・検討する。

1. DaybreakおよびCodex Securityの利用条件、申請手続き、対象プラン、費用、当社環境での提供形態を確認する。
1. Computer useの試行対象業務を選び、効果と必要な操作記録を確認する。
1. 見積書を受領後、社長へ契約を諮る。
